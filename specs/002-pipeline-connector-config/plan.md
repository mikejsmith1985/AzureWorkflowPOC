# Implementation Plan: Pipeline Connector Configuration Modal

**Branch**: `feature/pipeline-connector-config` | **Date**: 2026-06-18 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-pipeline-connector-config/spec.md`

## Summary

Add a configuration modal to the Blazor Server Pipeline dashboard that lets operators configure
all four external connectors (ServiceNow, Azure DevOps, LLM/Anthropic, Microsoft Teams), persist
those settings to the existing SQLite database via a new `ConnectorConfigRecord` EF Core entity,
encrypt secret values at rest using ASP.NET Core `IDataProtector`, surface per-connector
functional tests that exercise the real external service (not just network reachability), and
gate every pipeline run behind a live parallel pre-flight check across all four connectors.

## Technical Context

**Language/Version**: C# 12 / .NET 8.0

**Primary Dependencies**: ASP.NET Core 8.0 (Blazor Server, `IDataProtector`), Entity Framework Core
8.0.11 (SQLite, `IDbContextFactory<T>`), `Microsoft.TeamFoundation.WorkItemTracking.WebApi` 20.256.2,
Semantic Kernel 1.77.0, Tailwind CSS (CDN — existing dashboard palette)

**Storage**: SQLite via EF Core (`PipelineDbContext`) — new `ConnectorConfigRecord` entity, one row
per connector type

**Testing**: xUnit + Moq; unit tests 100% mocked (no I/O); integration tests against real connector
endpoints for functional-test methods

**Target Platform**: ASP.NET Core web server hosting Blazor Server

**Project Type**: Blazor Server web application — `DBAIAzure.Web`

**Performance Goals**: All four connector pre-flight tests complete in parallel within 30 seconds
(bounded by the slowest single test — SC-003 / SC-008)

**Constraints**:
- Secret field values never returned to UI after save; never persisted in plaintext (FR-004, FR-019)
- Connector config changes available to the pipeline on the next run without application restart (FR-014)
- Pre-flight runs a fresh live test at run time, not a cached result (Clarification 2026-06-18 Q3)

**Scale/Scope**: Single-tenant POC — 4 connector types, one configuration record per type

| Secret encryption at rest | ASP.NET Core Data Protection (`IDataProtector`) | None — framework built-in |

| Pre-flight check | `Task.WhenAll` over existing test methods (no scheduler needed) | `IConnectorHealthChecker` thin wrapper |
| Connector test methods | Extend existing connector classes with a `TestConnectionAsync()` method | `ServiceNowClient` (new outbound client — no existing one) |
