# Data Model: Visual Workflow Builder

**Feature**: 003-visual-workflow-builder | **Plan**: [plan.md](plan.md)

---

## Domain Models (`DBAIAzure.Core`)

### WorkflowDefinition

The canonical in-memory representation of a saved or in-progress workflow.

| Field | Type | Description |
|-------|------|-------------|
| `Id` | `Guid` | Stable identity — generated on first save, never changes |
| `Name` | `string` | User-assigned plain-language name (max 100 chars) |
| `OwnerId` | `string` | Authentication identity of the creating user |
| `Nodes` | `IReadOnlyList<WorkflowNode>` | All nodes in the workflow |
| `Edges` | `IReadOnlyList<WorkflowEdge>` | All connections between nodes |
| `Settings` | `WorkflowSettings` | Per-workflow configuration (timeout, design-skill answers) |
| `ChatHistory` | `IReadOnlyList<WorkflowChatMessage>` | Persisted chat conversation history |
| `GeneratedCode` | `string?` | Latest code generated by the Chat Assistant (null if never generated) |
| `CreatedAt` | `DateTimeOffset` | UTC timestamp of initial creation |
| `LastModifiedAt` | `DateTimeOffset` | UTC timestamp of last save |
| `ThumbnailSvg` | `string?` | SVG snapshot of canvas layout for gallery display |

**Uniqueness**: `Id` is globally unique. `Name` must be unique per `OwnerId` — enforced at
the repository layer with a descriptive error message ("You already have a workflow named X").

---

### WorkflowNode

A single node placed on the canvas.

| Field | Type | Description |
|-------|------|-------------|
| `Id` | `string` | Stable short ID (8-char hex, unique within a workflow) |
| `NodeType` | `WorkflowNodeType` | Category enum value |
| `Label` | `string` | Plain-language name shown on the canvas (max 50 chars) |
| `GoalPrompt` | `string?` | Agentic nodes only: the user's plain-language goal (Goal field) |
| `InputLabel` | `string?` | Agentic nodes only: plain-language name for this step's input |
| `OutputLabel` | `string?` | Agentic nodes only: plain-language description of what this step produces |
| `FunctionConfig` | `string?` | Function nodes only: JSON-serialized per-type config |
| `PositionX` | `double` | Canvas X coordinate (grid-snapped) |
| `PositionY` | `double` | Canvas Y coordinate (grid-snapped) |
| `IsConfigured` | `bool` | True when all required fields are populated |
| `InputPorts` | `IReadOnlyList<WorkflowPort>` | Named input connection points |
| `OutputPorts` | `IReadOnlyList<WorkflowPort>` | Named output connection points |

---

### WorkflowPort

A named connection point on a node.

| Field | Type | Description |
|-------|------|-------------|
| `Id` | `string` | Short ID unique within the node |
| `Label` | `string` | Plain-language label (e.g. "Approved", "Rejected", "Result") |
| `Direction` | `PortDirection` | `Input` or `Output` |

---

### WorkflowEdge

A directed connection between two ports.

| Field | Type | Description |
|-------|------|-------------|
| `Id` | `string` | Short ID unique within the workflow |
| `SourceNodeId` | `string` | ID of the source node |
| `SourcePortId` | `string` | ID of the output port on the source node |
| `TargetNodeId` | `string` | ID of the target node |
| `TargetPortId` | `string` | ID of the input port on the target node |
| `Label` | `string?` | Optional user-visible label on the arrow |

**Validity rule**: `SourcePortId` must be an `Output` port; `TargetPortId` must be an
`Input` port. No other structural validation is enforced at the data layer (cycles are
permitted — see research.md Decision 3).

---

### WorkflowSettings

Per-workflow configuration stored alongside the definition.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ExecutionTimeoutMinutes` | `int` | `5` | Maximum run duration before automatic timeout |
| `DesignSkillAnswers` | `Dictionary<string, string>` | `{}` | Keyed answers from the Workflow Design Skill (key = question fingerprint, value = user answer) |
| `LastRunInputDescription` | `string?` | `null` | Pre-populated for the run input form from the last execution |

---

### WorkflowChatMessage

One turn in the persisted chat conversation.

| Field | Type | Description |
|-------|------|-------------|
| `Role` | `ChatRole` | `User` or `Assistant` |
| `Content` | `string` | Message text (may contain a code block) |
| `IsCodeBlock` | `bool` | True when `Content` is a generated code block |
| `Timestamp` | `DateTimeOffset` | UTC send time |

---

### WorkflowNodeType (enum)

```
AgenticReason         — AI: reason, decide, generate, summarize, classify
FunctionRoute         — Deterministic: branch on a condition (named output per branch)
FunctionTransform     — Deterministic: reformat, extract, or reshape data
FunctionNotify        — Deterministic: send a notification to a configured target
FunctionData          — Deterministic: read from or write to a configured data source
HumanApproval         — HITL: pause and await explicit human approval before proceeding
```

**Palette categories** (maps `WorkflowNodeType` to display group):

| Category label | Node types |
|----------------|-----------|
| AI Steps | `AgenticReason` |
| Decisions & Routing | `FunctionRoute` |
| Data | `FunctionTransform`, `FunctionData` |
| Notifications | `FunctionNotify` |
| Human Steps | `HumanApproval` |

**Visual identity** (enforced by palette + canvas renderers):
- Agentic nodes: warm amber/gold border and icon
- Function nodes: cool blue/teal border and icon
- Human nodes: purple border and icon

---

### WorkflowRunStatus (enum)

```
NotStarted   — workflow exists on canvas but has never been run
Running      — execution is in progress
Paused       — awaiting human approval (HumanApproval node active)
Completed    — all nodes reached a terminal state successfully
Failed       — at least one node failed and no recovery path exists
TimedOut     — execution exceeded the configured timeout
Cancelled    — user clicked Stop
```

---

### NodeExecutionState (record)

Runtime-only (not persisted across sessions — cleared when the builder reloads).

| Field | Type | Description |
|-------|------|-------------|
| `NodeId` | `string` | Matches `WorkflowNode.Id` |
| `Status` | `NodeStatus` | `NotStarted \| Active \| Completed \| Failed \| Skipped \| TimedOut` |
| `OutputSummary` | `string?` | Brief plain-language description of the node's output |
| `FullOutput` | `string?` | Complete output text shown in the Run Output panel |
| `FailureReason` | `string?` | Plain-language failure message (null when not failed) |
| `StartedAt` | `DateTimeOffset?` | Null until node begins executing |
| `CompletedAt` | `DateTimeOffset?` | Null until node finishes |

## Persistence Entities (`DBAIAzure.Storage`)

### WorkflowDefinitionRecord

One row per saved workflow.

| Column | Type | Constraints |
|--------|------|-------------|
| `Id` | `TEXT` (GUID) | PRIMARY KEY, not null |
| `Name` | `TEXT` | NOT NULL |
| `OwnerId` | `TEXT` | NOT NULL |
| `NodesJson` | `TEXT` | JSON array of node objects, NOT NULL |
| `EdgesJson` | `TEXT` | JSON array of edge objects, NOT NULL |
| `SettingsJson` | `TEXT` | JSON object of WorkflowSettings, NOT NULL |
| `ChatHistoryJson` | `TEXT` | JSON array of chat messages, NOT NULL |
| `GeneratedCode` | `TEXT` | NULL when never generated |
| `ThumbnailSvg` | `TEXT` | NULL until first save |
| `CreatedAt` | `TEXT` (ISO-8601) | NOT NULL |
| `LastModifiedAt` | `TEXT` (ISO-8601) | NOT NULL |

**Unique index**: `(OwnerId, Name)` — enforces per-user name uniqueness at the database level.
**Index**: `OwnerId` — supports efficient personal gallery queries.

## State Transitions

### Workflow lifecycle

```
[Unsaved Draft]
    │
    ▼ user clicks Save
[Saved / NotStarted]
    │
    ├─▶ user clicks Run ──▶ [Running]
    │                            │
    │                            ├──▶ [Paused / Awaiting Human]
    │                            │         │
    │                            │         └──▶ approval given ──▶ [Running]
    │                            │
    │                            ├──▶ all nodes complete ──▶ [Completed]
    │                            ├──▶ node fails, no recovery ──▶ [Failed]
    │                            ├──▶ timeout reached ──▶ [TimedOut]
    │                            └──▶ user clicks Stop ──▶ [Cancelled]
    │
    └─▶ user edits and saves ──▶ [Saved / NotStarted]  (run status is reset on topology change)
```

### Node execution lifecycle

```
NotStarted ──▶ Active ──▶ Completed
                    │
                    ├──▶ Failed ──▶ downstream nodes: Skipped
                    └──▶ TimedOut ──▶ downstream nodes: Skipped
```

## Repository Contract Summary

See [contracts/iworkflow-repository.md](contracts/iworkflow-repository.md) for the full
interface contract. Key operations:

- `SaveAsync(WorkflowDefinition, CancellationToken)` — upsert by `Id`; enforces `(OwnerId, Name)` uniqueness
- `GetAsync(Guid id, string ownerId, CancellationToken)` — personal access control enforced here
- `ListByOwnerAsync(string ownerId, CancellationToken)` — gallery query
- `DeleteAsync(Guid id, string ownerId, CancellationToken)` — only owner can delete
- `ExistsAsync(Guid id, string ownerId, CancellationToken)` — pre-delete confirmation check
