# Data Model: Production Platform Parity

All entities below are new unless marked **EXTEND**. Entities in `DBAIAzure.Storage/Entities/`
are EF Core entities; entities in `DBAIAzure.Core/Models/` are domain records.

---

## WorkflowRunRecord (domain model)

`DBAIAzure.Core/Models/WorkflowRunRecord.cs`

```
WorkflowRunRecord
├── RunId              : string          — GUID short-form (8 hex chars), generated by orchestrator
├── WorkflowId         : string          — FK to WorkflowDefinition.Id
├── WorkflowName       : string          — snapshot of name at run start (denormalised for history display)
├── Status             : WorkflowRunStatus  — Running | Paused | Completed | Failed | TimedOut | Cancelled
├── TriggeredBy        : string          — identity of initiating user (SignalR connection user or "system")
├── StartedAt          : DateTimeOffset
├── SuspendedAt        : DateTimeOffset? — set when Status transitions to Paused
├── ResumedAt          : DateTimeOffset? — set when SubmitApproval resolves the TCS
├── CompletedAt        : DateTimeOffset? — set at any terminal transition
└── FailureReason      : string?         — non-null only when Status = Failed
```

**Constraints**: `RunId` is the primary key. `Status` follows `WorkflowRunStatus` (no backward
transitions — append-only state machine). `SuspendedAt` is set on `Paused`; `ResumedAt` on first
exit from `Paused`; `CompletedAt` on any terminal state.

## WorkflowExecutionEvent (domain model)

`DBAIAzure.Core/Models/WorkflowExecutionEvent.cs`

```
WorkflowExecutionEvent
├── EventId            : Guid            — generated on creation
├── RunId              : string          — FK to WorkflowRunRecord.RunId
├── NodeId             : string          — ID of the step/node that fired the event
├── NodeLabel          : string          — display label snapshot
├── EventType          : WorkflowEventType  — StepStarted | StepCompleted | StepFailed |
│                                            StepSkipped | LlmCallCompleted | RunPaused | RunResumed
├── OccurredAt         : DateTimeOffset
├── DurationMs         : long?           — set for StepCompleted/StepFailed/LlmCallCompleted
├── Outcome            : string?         — human-readable outcome or error message
├── LlmModelName       : string?         — non-null for LlmCallCompleted events only
├── LlmInputTokens     : int?            — non-null for LlmCallCompleted events only
└── LlmOutputTokens    : int?            — non-null for LlmCallCompleted events only
```

**State transitions for WorkflowEventType**:
```
StepStarted → StepCompleted | StepFailed | StepSkipped
StepStarted (AI step) → LlmCallCompleted (emitted by IFunctionInvocationFilter) → StepCompleted
Paused  → RunPaused  (emitted when WorkflowRunStatus becomes Paused)
RunPaused → RunResumed (emitted when SubmitApproval resolves)
```

## WorkflowRunRecord — EXTENDED WorkflowRunStatus

`DBAIAzure.Core/Models/WorkflowRunStatus.cs` — **EXTEND** (no renames; `NotStarted` retained)

The existing enum already matches the clarified 6-state model:

| Spec name | Code name | Meaning |
|-----------|-----------|---------|
| Running   | Running   | Background task active |
| Suspended | **Paused** | Awaiting human signal |
| Succeeded | **Completed** | All nodes finished without error |
| Failed    | Failed    | Unrecoverable error |
| TimedOut  | TimedOut  | Watchdog terminated |
| Cancelled | Cancelled | Operator requested stop |

No code changes required to `WorkflowRunStatus`. `NotStarted` retained as initial marker.

## WorkflowGenerationResult (LLM structured output)

`DBAIAzure.Core/Models/WorkflowGenerationResult.cs`

Used as `T` in `IStructuredCompletionService.GetStructuredAsync<WorkflowGenerationResult>(...)`.

```
WorkflowGenerationResult
├── Nodes              : GeneratedNode[]
│   ├── Id             : string          — temp ID for edge wiring (e.g. "n1", "n2")
│   ├── NodeType       : WorkflowNodeType
│   ├── Label          : string          — plain-language name
│   └── GoalPrompt     : string?         — for AI and Trigger nodes only
├── Edges              : GeneratedEdge[]
│   ├── SourceNodeId   : string          — matches a GeneratedNode.Id
│   └── TargetNodeId   : string          — matches a GeneratedNode.Id
└── ClarifyingQuestion : string?         — non-null when the description was ambiguous (FR-23.3)
```

If `ClarifyingQuestion` is non-null, `Nodes` and `Edges` will be empty and the UI prompts the
user to answer before re-submitting.
